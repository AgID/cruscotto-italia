API e accesso ai dati

I dati di Cruscotto Italia si possono leggere anche da programma. Ci sono due servizi, entrambi pubblici, gratuiti e senza registrazione: un'API REST di sola lettura per applicazioni e script, e un server MCP per gli assistenti di intelligenza artificiale.

API REST

Ogni fonte ha un file per comune, identificato dal codice ISTAT a 6 cifre. Si leggono con una semplice richiesta GET all'indirizzo https://cruscotto-italia.dati.gov.it/data/<fonte>/<codice ISTAT>.json. Non servono chiavi e le richieste da browser sono consentite (CORS aperto).

Esempi

Popolazione residente di Lecce (codice ISTAT 075035):

curl https://cruscotto-italia.dati.gov.it/data/demografia/075035.json

Lo stesso in Python, senza librerie esterne:

import json, urllib.request

url = "https://cruscotto-italia.dati.gov.it/data/demografia/075035.json"
with urllib.request.urlopen(url) as r:
    dati = json.load(r)
print(dati["comune"], dati["popolazione_totale"])

Codici ISTAT

  • L'elenco dei codici dei comuni vigenti è in /data/istat-coords.json.
  • I codici precedenti dei comuni ricodificati (per esempio la riforma delle province sarde del 2026) funzionano ancora: il server risponde con i dati del comune attuale. La tabella delle variazioni è in /data/lookup/variazioni_istat.json.

Aggiornamento

  • Ogni fonte segue il calendario di pubblicazione del suo titolare. La data a cui si riferisce il dato è indicata dentro il file, nei campi che iniziano con il trattino basso (per esempio _anno_riferimento).
  • La data dell'ultima rigenerazione del file è nell'intestazione Last-Modified. Con If-None-Match o If-Modified-Since il server risponde 304 se il file non è cambiato.

Riferimento OpenAPI

Tutti i percorsi, con il titolare di ciascun dato, sono descritti nel documento openapi.json (OpenAPI 3.1), che si può importare in qualsiasi strumento compatibile. Qui sotto la stessa descrizione in forma navigabile.

La prova delle chiamate con «Try it out» serve a vedere com'è fatto il dato, non a scaricarlo: gli elenchi della risposta sono limitati a 1000 elementi e i file più pesanti (civici completi, sezioni di censimento, catasto, scheda completa del comune) non si provano dalla pagina. Per i dati completi usare le chiamate da programma o da riga di comando, come negli esempi sopra.

Server MCP

Il server Model Context Protocol (apre in nuova scheda) permette a un assistente AI (Claude, ChatGPT e altri compatibili) di interrogare i dati con domande in linguaggio naturale.

  • Indirizzo: https://cruscotto-italia-mcp.agid.workers.dev/mcp
  • Protocollo: MCP, revisione 2025-11-25, trasporto HTTP
  • Tutti gli strumenti sono di sola lettura e non richiedono autenticazione.

Verificare la versione in esercizio

/health restituisce versione e build: è l'identificativo del codice del server, uguale a quello della cartella worker/ nel repository pubblico (git rev-parse <commit>:worker). Così chiunque può controllare che il server in esercizio esegua il codice pubblicato.

Strumenti client

Non sono servizi a sé, ma strumenti pronti che usano i due servizi sopra.

  • Skill per assistenti AI: documenta gli strumenti MCP, lo schema delle sezioni dati e i modi d'uso consigliati.
  • Skill CLI: script Python 3 senza dipendenze che legge direttamente l'API REST e filtra i dati prima di caricarli. Si usa con un assistente AI o da solo, in un terminale.

Le versioni correnti da scaricare e le guide passo-passo per collegare Claude e ChatGPT sono nella pagina Il progetto, sezione Accesso.

Chi vuole i dati di un solo comune tutti insieme può scaricare l'archivio ZIP dalla pagina del comune: contiene i file JSON, la legenda dei campi e le attribuzioni.

Condizioni d'uso

  • Licenza: i dati sono rilasciati con licenza CC BY 4.0 (apre in nuova scheda). Va citato il titolare del dato di origine, indicato per ogni percorso nel riferimento OpenAPI, e Cruscotto Italia (AgID).
  • Accesso: libero, gratuito, senza registrazione e senza chiavi.
  • Titolarità: Cruscotto Italia ricompone dati già pubblicati dalle amministrazioni titolari e non li sostituisce. Per gli usi ufficiali fa fede la pubblicazione del titolare.

Limiti di utilizzo

Per mantenere il servizio disponibile a tutti valgono i limiti seguenti, applicati automaticamente per indirizzo IP.

RisorsaLimite
Endpoint MCP /mcp60 richieste al minuto
Shard per comune /data/<fonte>/<istat>.json2 richieste al secondo, picchi fino a 80
Archivi aggregati e _full10 richieste al secondo, picchi fino a 60
Connessioni simultanee su /data/8
Controlli di disponibilitàusare /health: non sono ammessi controlli ripetuti sui tool dati
Blocco automaticooltre 3.000 richieste in 10 minuti: 24 ore
Blocchi ripetutila durata raddoppia a ogni recidiva, fino a 4 settimane

Buone pratiche

  • Dichiarare uno User-Agent riconoscibile, con il nome del progetto e un recapito: un client che si identifica non viene scambiato per traffico anomalo.
  • Per i controlli di disponibilità usare /health, non i tool dati: è l'endpoint previsto allo scopo e non consuma il limite MCP.
  • Per scaricare molti comuni usare l'API REST, non chiamate MCP ripetute: è più veloce per chi scarica e più leggero per il servizio. Le richieste condizionali (If-None-Match, If-Modified-Since) evitano di riscaricare i file non cambiati.
  • Le risposte indicano in Cache-Control per quanto tempo si possono riutilizzare.
  • Superato un limite la risposta è 429: attendere e riprovare con intervalli crescenti, non insistere.

Per usi che richiedono volumi superiori a questi limiti, o in caso di dubbi, scrivere a dati@agid.gov.it: i limiti sono una tutela del servizio, non una chiusura verso il riuso.
