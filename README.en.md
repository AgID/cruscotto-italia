# Cruscotto Italia

[🇮🇹 Italiano](README.md) · 🇬🇧 English

> Institutional, data-driven transparency platform for Italian municipalities.
> It federates the main datasets published by national institutional bodies
> and recomposes them per municipality, exposing a public web interface and a
> Model Context Protocol endpoint for AI agents.

[![Deploy Worker](https://github.com/AgID/cruscotto-italia/actions/workflows/deploy-worker.yml/badge.svg)](https://github.com/AgID/cruscotto-italia/actions/workflows/deploy-worker.yml)

## Federated data

Searching for a municipality ("Lecce") returns a 360° view of:

- 🏗️ **Public contracts** (ANAC — national anti-corruption authority, OCDS-IT)
- 🚧 **Public works** (BDAP-MOP — Ministry of Economy and Finance / State General Accounting Office)
- 💰 **Cash flows** (SIOPE — MEF/RGS): payments, receipts and cash balance
- 🇪🇺 **NRRP projects** (Italia Domani — ReGiS system; Italy's Recovery and Resilience Plan)
- 👥 **Municipal demographics** (ISTAT POSAS — resident population by age and sex)
- 🎓 **Socio-economic profile** (ISTAT permanent census)
- 🏨 **Tourism** (ISTAT accommodation capacity + provincial flows)
- 🏫 **Schools** (MIUR — registry of state schools)
- 👶 **Demographic dynamics** (ISTAT D7B — monthly demographic balance: births, deaths, natural and migration balance, source ANPR)
- 🌫️ **Air quality** (ISPRA SNPA — PM10/PM2.5/NO2 per station: ISPRA historical series, Environmental Data Yearbook, SNPA preliminary tables for years not yet consolidated)
- 🏞️ **Land and territory** (ISPRA — land consumption, IdroGEO landslides and floods, municipal waste)
- 🌋 **Seismic classification** (Civil Protection Department)
- ⛰️ **Terrain morphology** (CNR-IRPI — 5 m HR-DTM: elevation, slope, aspect, geomorphology, solar irradiance)
- 🚗 **Vehicle fleet and road accidents** (ISTAT 41_993 + ACI Linked Open Data)
- 💶 **Income and taxation** (MEF — personal income tax returns, IRPEF)
- 🏛️ **Public real estate** (MEF Treasury Department — Public Property Assets)
- 🏠 **House numbers and streets** (ANNCSU — Revenue Agency, HVD open data)
- 💊 **Local healthcare** (Ministry of Health — pharmacies, para-pharmacies, hospital beds)
- ⚡ **EV charging points** (GSE/MASE — National Single Platform, PUN)
- 📶 **Broadband** (AGCOM Broadband Map — FTTH/FTTC coverage per municipality)
- ⛽ **Fuel stations and prices** (MIMIT — Fuel Price Observatory)
- 🤝 **Third-sector organisations** (Ministry of Labour — RUNTS national register, Legislative Decree 117/2017: ODV, APS, EF, IS, SMS, ETS)
- 🏭 **Businesses and employees** (ISTAT — ASIA UL, 2018-2023 series)
- 🚌 **Commuting** (ISTAT permanent census 2021 — origin/destination work-trip matrix)
- 🗺️ **Census by enumeration area** (ISTAT Territorial Bases 2021 + 2023 census variables — ~756,000 enumeration areas with 127 demographic/housing variables each)
- 🏛️ **Cultural heritage** (Ministry of Culture — ICCD ArCo for protected immovable heritage: churches, palaces, castles, archaeology, villas, monuments, superintendencies; Cultural-ON DBUnico 2.0 for visitable cultural venues: museums, libraries, archives with opening hours and contacts)
- 🗺️ **Cadastral cartography** (Revenue Agency — Land Registry INSPIRE: parcels and map sheets for 19 Italian regions, six-monthly bulk dataset, CC BY 4.0)
- 🏘️ **Property market values** (Revenue Agency — OMI: sale and rental values in €/m² by homogeneous sub-municipal zone, broken down by property type, intended use and state of repair, with the geographic boundaries of each zone; 24,101 priced zones across 7,885 municipalities, six-monthly, CC BY 4.0)
- 🌤️ **Weather forecasts** (ItaliaMeteo — ICON-2I, 2.2 km grid: temperature, precipitation, wind, snow, cloud cover, 73 hourly steps 0–72h, updated twice a day, CC BY 4.0 HVD Meteorological)

The full list, with licences, update frequencies and direct links to the
institutional sources, is available on the public `about.html` page of the
site.

The data is also exposed as a **DCAT-AP_IT catalogue** (one `dcat:Dataset`
per municipality, generated by `etl/sources/dcat_catalog.py`) for harvesting
by [dati.gov.it](https://www.dati.gov.it), the Italian national open data
portal.

Everything is recomposed on the **ISTAT municipal registry backbone**
(~7,896 municipalities) integrated with `IPA` (the Index of Digital Domiciles
of the Public Administration, maintained by AgID).

### ETL schedule

Times in **Italian time** (the VM cron uses the Europe/Rome time zone), except the ACI and ISTAT workflows on GitHub Actions (UTC).

| **Daily** (05:00, 11:00, 16:00, 22:00) | ItaliaMeteo ICON-2I weather forecasts | AgID VM cron | automatic |
| **Daily** (11:00 and 16:00) | dashboard rebuild (aggregate of all sections) | AgID VM cron | automatic |
| **Daily** (09:30) | freshness check: ETL runs and data period per source | AgID VM cron | automatic |
| **Weekly** (Monday 04:00-06:00) | ANAC OCDS (awards in the last 12 published monthly files, deduplicated), NRRP, RUNTS, SIOPE, dashboard | AgID VM cron | automatic |
| **Monthly** (day 5, 04:00-08:40) | registry, BDAP-MOP, SIOPE, ANNCSU, AGCOM broadband, Cultural-ON, cultural heritage, dashboard | AgID VM cron | automatic |
| **Annual** (1 Feb / 1 Apr / 1 Jul, 04:00-14:00) | POSAS demographics and population balance, census profile, air quality, ASIA, tourism, seismic classification, territory, vehicles (ACI CSVs from GitHub Actions), IRPEF income, public real estate, dashboard | AgID VM cron | automatic |
| **Annual** (5 September, 04:00) | MIUR schools (school year just started) | AgID VM cron | automatic |
| **Six-monthly** (check on the 1st of each month, 03:00) | AGE cadastral maps (parcels + sheets, 19 regions): downloads only when AGE file sizes change | AgID VM cron | automatic |
| **Six-monthly** (daily sentinel 03:20) | AGE OMI quotations (zones + perimeters): `omi_semestrale.sh` checks the published semesters every day and starts the collection only when a new one appears (published by 15 March and 15 October, no fixed date) | AgID VM cron | automatic |
| **Ten-yearly** (manual, next 2031) | census Basi Territoriali (sections + 119 vars) | manual run `python -m etl.sources.censimento` on the VM | `workflow_dispatch` |
| **ACI on Actions** (1 Feb / 1 Apr / 1 Jul, 04:00 UTC) | ACI LOD first-registration CSVs, then fetched by the VM with `fetch_aci_artifact.py` | GitHub Actions `ubuntu-latest` | `schedule` + `workflow_dispatch` |
| **ISTAT on Actions** (1 Feb / 1 Apr / 1 Jul, 02:00 UTC) | SDMX download of vehicle fleet, road accidents, accommodation capacity and tourist flows, split across 8 runners; the VM fetches them with `fetch_istat_artifact.py` and the ETLs run with `--solo-cache` | GitHub Actions `ubuntu-latest` | `schedule` + `workflow_dispatch` |
| **Manual fallback** | istat_profilo, asia, pendolarismo | GitHub Actions `ubuntu-latest` | `workflow_dispatch` |

### Why two separate runners

**Italian institutional sources** sit behind WAFs (F5 Volterra, Akamai, etc.)
that reject requests from cloud IPs (Azure GitHub Actions, AWS, GCP) with
HTTP 403. They are therefore queried only from the AgID VM (Italian IP).

The only exception is **ACI LOD** (`lod.aci.it`), not reachable from the
VM: the `etl-aci-refresh.yml` workflow downloads the CSVs on GitHub Actions
and the VM fetches them with
[`scripts/etl/fetch_aci_artifact.py`](scripts/etl/fetch_aci_artifact.py)
before the vehicles ETL.

**ISTAT esploradati** blocks the VM's IP after about 100-130 SDMX requests,
even below the declared 5 queries/minute (October 2026). For vehicle fleet,
road accidents and tourism the download therefore runs on Actions
([`istat-download.yml`](.github/workflows/istat-download.yml)): municipalities
are split into 8 parts, each on a different runner with fewer than 40
requests. The `istat-raw` artifact holds the merged CSVs and a
`manifest.json` with years and row counts; the VM fetches it with
[`scripts/etl/fetch_istat_artifact.py`](scripts/etl/fetch_istat_artifact.py),
which checks row counts before replacing the cache, and runs `veicoli` and
`istat_turismo` with `--solo-cache` (no request to ISTAT).

For the other sources, ISTAT limits requests that are too large or too
frequent (above 35 municipality codes per request it answers 400). The
other ISTAT ETLs run from the VM and download in sequential batches of 35 municipalities with a pause
([`etl/lib/istat_sdmx.py`](etl/lib/istat_sdmx.py)). The ISTAT workflows on
Actions (profile, ASIA, commuting) are kept only as a manual fallback: no VM
cron downloads their artifacts.

The weekly/monthly/annual workflows in `.github/workflows/` are therefore
**documentary smoke tests**: a reviewer can open them from the Actions UI to
read the Python commands executed by the VM cron, but on ubuntu-latest they
fail with 403 (WAF). The real data producer is the `/etc/cron.d/cruscotto-etl`
cron on the AgID VM, never the workflows.

## MCP API for AI agents

Cruscotto Italia exposes a [Model Context Protocol](https://modelcontextprotocol.io)
server so that compatible AI chatbots (Claude, ChatGPT via wrapper, OpenWebUI,
custom agents) can query civic data.

**Public endpoint** (AgID Worker): `https://cruscotto-italia-mcp.agid.workers.dev/mcp`

**Exposed tools** (6 semantic + 2 compatibility):

- `mcp_info` — service metadata, list of integrated sources, licences
- `search_comune` — search by name → ISTAT code (handles homonyms)
- `comune_kpi` — summary KPIs for a municipality (~620 tokens, the first
  tool to call for point queries and comparisons)
- `comune_dashboard` — unified view: a single call returns the
  municipality's sections (registry, demographics, contracts, BDAP-MOP
  public works with CUP project detail, ANNCSU, healthcare, broadband,
  cultural heritage, etc.)
- `anncsu_civico_search` — point queries on certified house numbers with
  server-side filters (street name, house number)
- `censimento_sezione_search` — ranking or lookup on the 127 raw census
  variables of the 2023 Permanent Census at the level of a single
  sub-municipal enumeration area (lookup mode with `sez_id`, or ranking with
  `var_name` ± `denominator_var` for percentages)
- `search` and `fetch` — fixed schema required by ChatGPT's custom MCP
  connector; they wrap `search_comune` and `comune_dashboard`

The server implements the MCP 2025-11-25 specification (stateless JSON-RPC
2.0, Streamable HTTP): every tool declares an `outputSchema`, returns
`structuredContent` and is annotated as read-only. `mcp_info` and `/health`
expose the Worker version and the git tree hash of `worker/` (`BUILD_TREE`),
which can be verified against the repository with
`git rev-parse <commit>:worker`.

**Cadastral cartography** (Revenue Agency parcels and sheets) is instead
exposed as REST at `/data/catasto_full/<istat>_map.geojson.gz` and
`/data/catasto_full/<istat>_ple.geojson.gz` (or split by sheet for large
municipalities). For usage patterns and examples see the Claude MCP skill
(cadastre section) and the README inside the `/data/<istat>.zip` bundle.

**Rate limit**: 60 requests/minute per IP.

### Setup on Claude.ai

1. Settings → Connectors → Add custom connector
2. URL: `https://cruscotto-italia-mcp.agid.workers.dev/mcp`
3. Authentication: none

### Claude skill (optional)

A Claude skill documents how to use the connector (inventory of the 6 tools,
`comune_dashboard` schema, operational patterns and per-section caveats, REST
access to the cadastral cartography). Current version:
`https://cruscotto-italia.dati.gov.it/data/skills/cruscotto-italia-workflow-v2.12.0.zip`.
`cruscotto-cli-v0.2.0.zip` is also available: an executable skill that queries
the static JSON shards directly without going through the MCP server (full
list with history in `docs/skills/README.md`).

### Examples of supported questions

- "Tell me about Lecce" — full overview
- "How many NRRP projects does Bergamo have?" — NRRP focus
- "Demographic comparison between Milan and Rome" — cross-municipality orchestration
- "How many active pharmacies are there in Matera?" — local healthcare
- "How many active EV charging points are there in Turin, and what share is HPC/ultra-fast?"
- "How many ANNCSU-certified house numbers are there on Via Roma in Lecce?"
- "What is the FTTH coverage in Bergamo? Compare it with Brescia."
- "How much does self-service diesel cost in Lecce compared with the national average?"
- "How many third-sector organisations (ODV/APS) does Matera have? How many are enrolled in the 5x1000 scheme?"
- "How many commuters leave Bergamo for Milan every day?"
- "How many ICCD ArCo protected churches are there in Lecce?"

### Known limits

- Tools are optimised for **per-municipality** queries, not for
  cross-municipality aggregates (e.g. "top 10 NRRP per region" requires N
  calls).
- The MCP is read-only: no side effects, no writes.
- Cadastral cartography (parcels/sheets) is NOT exposed via MCP but via
  direct REST: the MCP tools do not read cadastral geometries; the frontend
  and agents consume them directly from `/data/catasto_full/`.

## Local development

### Prerequisites

- Node.js ≥ 22 (required by vitest 5 and the Worker CI)
- Python ≥ 3.12
- `wrangler` CLI (`npm i -g wrangler`) for the Worker

### Setup

```bash
git clone https://github.com/AgID/cruscotto-italia.git
cd cruscotto-italia

# Worker (Cloudflare)
cd worker
npm install
npm run dev   # http://localhost:8787

# Frontend (static)
cd ../frontend
python3 -m http.server 8000   # http://localhost:8000

# Python ETL — example: download PUN charging points into /tmp/test/
cd ..
pip install -r etl/requirements.txt
DATA_DIR=/tmp/test python -m etl.sources.pun --outdir=/tmp/test/pun
```

All ETLs write to the local filesystem (`--target=local`, now the only
supported target). Output goes to `DATA_DIR/<source>/<istat>.json`, with
`DATA_DIR` overridable via environment (default
`/var/www/cruscotto-italia/data/`).

### Deploy

Frontend and ETL data run on the AgID VM via cron — there is no "frontend
deploy" in a CI/CD sense: the site is a git pull on the VM.

The MCP Worker is deployed to AgID's Cloudflare account with:

```bash
cd worker
npm run typecheck && npm run deploy
```

Requires `CLOUDFLARE_API_TOKEN` for the AgID account in the shell profile.

## Checking data freshness

Each municipality's `comune_dashboard` contains a top-level `_generated_at`
field (ISO-8601 UTC timestamp) indicating when the AgID VM last rebuilt the
A1 aggregate. Example check:

```bash
curl -s -X POST "https://cruscotto-italia-mcp.agid.workers.dev/mcp" \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","method":"tools/call","id":1,
       "params":{"name":"comune_dashboard","arguments":{"istat_code":"075035"}}}' \
  | jq '.result.content[0].text | fromjson | {_generated_at, _missing}'
```

Under normal operating conditions `_generated_at` is recent (≤ 24h) and
`_missing` is empty or lists only sources for which the municipality has no
upstream data (e.g. very small municipalities with no charging points or fuel
stations).

Note: `_generated_at` tells when the aggregate was rebuilt, not which period
the data refers to. Sections with a reference period expose it in
`_data_period` (e.g. `agcom_bbmap`, `omi`): check that field to know whether
a source is up to date.

The same principle drives the automatic check. Every morning
`scripts/etl/freshness_check.py` verifies, besides ETL execution, the
**data period** of non-daily sources (`CONTROLLI_CONTENUTO`: date age for
monthly sources, minimum expected year for annual ones, month window for
ANAC) and raises an alert when it falls behind the source's publication
calendar. Since the 05/10/2026 audit the ETLs follow these rules: source
years and editions resolved at runtime and never hard-coded, caches that
expire (or carry the period in their name), downloads written to a
temporary file and renamed on completion, ISTAT requests in sequential
batches of 35 municipalities.
